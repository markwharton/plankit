title: A configured repository loads the plugin for its teammates
---

**A configured repository carries the plugin for its teammates.** `pk
init` now adds two entries to `.claude/settings.json` and commits them
with the policy: the plankit marketplace under `extraKnownMarketplaces`
and `plankit@plankit` under `enabledPlugins`. A teammate who trusts the
folder has the marketplace and is one `/plugin install plankit@plankit`
from the plugin; Claude Code names it in the plugin errors tab until
then. Project settings apply over user settings, so the entry holds for
a teammate who disabled the plugin for themselves. `pk help init` has
the run in full.

**The settings file stays yours.** The two entries are spliced in, so
every other byte of the file, its key order, spacing, hooks, and
permissions, comes back as it went in. An entry already under its key,
pointing somewhere else, is left as it is and reported. A file with
uncommitted changes, or one that does not parse, stops the run before
anything is written and names what to fix. pk never writes
`permissions`; the allow rule in the README is still yours to add.

**A repository configured before this release is one edit away.**
`pk status` notes a settings file that lacks an entry and prints the
JSON to merge in, rendered by the same code init uses. `--quiet` drops
the note as it drops the others.

```
pk status
```
