title: The plans directory is yours to name
---

**A plan revised after approval is preserved again.** When a plan is
approved, the preserve hook records its path in `.git/pk-pending-plan`,
and a typed `pk preserve` consumes that pointer. A plan you revise after
that has no pointer, so `pk preserve --plan` names the file itself. The
same rules hold: the path is a Claude Code plan under `~/.claude/plans/`,
identical bytes report the record that already exists, and the revision
becomes the next sequence number for the day. While the pointer names a
different plan, `--plan` refuses and names both files, so the pending
plan is preserved first. `--dry-run` previews the filename and the
commit. `pk help preserve` says how the pointer is set and where it
lives.

```
pk preserve --plan ~/.claude/plans/<name>.md
```

**The plans directory is yours to name.** `preserve.dir` in `.pk.json`
is where preserved plans are written, relative to the repository root.
With the key absent it is `docs/plans`, so a configured repository is
unchanged. Every reader follows the one key: preserve writes there,
protect keeps it immutable, the brief tells each session where it is,
and `pk status` reports it. A value that leaves the repository, or is
not a clean forward-slash path, fails the file when it loads and names
the key. `pk init` writes the key explicitly.

```
"preserve": { "dir": "documentation/plans" }
```

**A typed `pk preserve` needs the policy file.** In a repository with no
`.pk.json`, the command now says so and names `pk init`, instead of
committing to `docs/plans` as if the repository were configured. The
approval hook is unchanged: without the file it does nothing.
