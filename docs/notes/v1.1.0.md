title: Releases start when you ask
---

**A release starts when you ask for one.** `pk ship` is the developer's
command. A session runs it when you ask for a release, not on its own
reading of a preview. The ship page says so, and says which pk commands
are safe for a session to allowlist: the ones that only read or stage.
`pk ship` and `pk release` publish, so they stay yours. `pk help ship`
prints the page.

**The release commands say where a release stands.** A release is
pending while its tag is absent, and finished once the tag exists. So a
second `pk ship` reports nothing to release and stops, instead of
announcing a release that already shipped. `pk release` names where a
tag sits, on HEAD or on another commit, and `pk preserve` says when no
plan is waiting rather than returning without a word.

**Every session is told which plugin version it runs.** The brief runs
the plugin's own binary, so the first sentence a session reads names
that version: plankit 1.1.0 is configured in this repository. That is
the plugin's version, and not necessarily the `pk` on your PATH, which
`pk version` reports. The README and `pk help overview` give the
commands that update the plugin.
