title: pull and cherry-pick count as mutations
---

**`pk guard` denies `am`, `cherry-pick`, `pull`, and `revert` on a
protected branch.** Each puts commits on the branch that is checked
out, which is what the branch policy exists to stop; the list was
`commit`, `merge`, `push`, `rebase`, and `reset`. guard also reads
quoted words, a background `&`, subshells, and shell keywords such as
`then`, so `git -C "my dir" push` and `(git push)` are seen as the
push they are. `guard.mode` is still the dial. `pk help guard` lists
the nine subcommands and the forms guard does not read: `sudo`,
`sh -c`, and `eval`.

```
pk guard: branch "main" is protected. Switch to your development branch and use pk release from there.
```

**`pk changelog` leaves the tree clean when a version file or a hook
fails.** Everything the run wrote is put back, a hook's own edits
included, and nothing is committed, so a `pk ship` that fails leaves
the repository as it found it. An origin that cannot be reached is exit
2 with a hint, where it was exit 3. A `v`-prefixed tag that is not a
version, such as `vnext`, no longer anchors a release or blocks one.

```
Error: preCommit hook failed: exit status 1
Hint: nothing was committed; the tree is clean
```

**`pk preserve` commits a plan whose earlier commit failed.** A commit
refused by a pre-commit hook left the plan file in place, and the next
run reported the plan as already preserved; now the next run commits
it. A typed `pk preserve` names the failure and exits non-zero, and the
hook's failure is shown in the session with exit 1 rather than hidden
behind exit 0.

```
Error: git commit failed: exit status 1
```
