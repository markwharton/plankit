title: The commits decide the version
---

**The commits decide the version, and guard asks before an override
lowers it.** `pk ship --dry-run` shows the bump the commits infer, and
that bump is the release; a number named earlier in a plan or a
conversation is a guess. A `--bump` lower than the inference, patch over
a `feat` or minor over a breaking change, now gets a question from guard
in a session, with the commits that call for the higher bump in the
reason, the way a breaking marker does. The dial is `guard.bump`, `ask`
by default, `off` to keep the rule without the question. At a terminal
nothing is in the way: `--bump` is the developer's, and changelog names
the override next to the version it generates.

```
Generating v0.8.1 (--bump patch; the commits infer minor)
```

**The ship and changelog pages say what to do with an unexpected
version.** Stop and say so. A commit whose type is wrong is fixed by
amending the type, while it is unpushed, never by overriding the bump.
`--bump` and `--exclude` are used only when the developer asks, with the
value given. `pk help ship`, Deciding the version, has the rule, and the brief
carries a sentence of it into every session.

**A pending plan can be discarded, and status shows it.** The preserve
hook records the approved plan in the repository the session runs in.
When the plan belongs to another repository and was preserved there
with `--plan`, `pk preserve --discard` drops the pointer left behind and
names the plan it pointed at, in place of a hand delete under `.git/`.
`pk status` shows the pending plan on its own line, marks one whose file
is gone, and notes the two ways out.

```
pk preserve --discard
```
