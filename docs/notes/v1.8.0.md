title: Status names the flow
---

**`pk status` names the flow on its release line.** Merge flow now
reads as trunk flow already did, so one line says which flow a
repository is in and what `pk ship` will do there.

```
release:   merge flow: pk ship merges develop into main and tags it
release:   trunk flow: pk ship tags main, origin's default branch
```

**`pk help release` says which flow to choose and how to move between
them.** Two flows has the rule in a paragraph: merge flow where
unreleased work has somewhere to run, trunk flow where a second
environment would have to be built, and the switch either way is a
config change and a branch. Tags made under one flow stay valid under
the other.
