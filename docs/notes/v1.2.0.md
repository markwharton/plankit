title: A repository is configured in one run
---

**A repository is configured in one run.** `pk init` writes `.pk.json`
and commits it, tags `v0.0.0` so the release commands have a starting
point, and prints the brief, so the session that ran it is told the
policy the way every later session is. When the release branch is the
only branch, it creates a working branch and checks it out: `develop`,
or the name you give `--branch`. A repository that already has a working
branch keeps it. Nothing is pushed unless you say `--push`, and
`--no-commit` leaves the file for you to read and commit yourself.
`pk help init` has the rest.

```
pk init
```

**`pk status` says what is left to do.** A repository configured by hand,
or by an earlier `pk init`, can have commits with no tag, or the release
branch as its only branch. Status now notes each and names the command
that finishes the setup, so the state the release commands rely on is
visible rather than assumed.

**Any command page is enough to run the command.** `--plain`,
`--project-dir`, and `--quiet` work on every command, and each command's
page now ends with that line, pointing at `pk help help` for the full
block. A session that has read one page can run pk against another
directory without a second lookup.
